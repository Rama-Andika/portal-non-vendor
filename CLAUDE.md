# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Portal Non Vendor" — a React 19 + Vite SPA/PWA where non-vendor users submit invoices ("portal requests") and settlements, and admins review them. The UI defaults to Indonesian; many code comments and all `plans/` docs are written in Indonesian.

## Commands

```bash
npm run dev          # Vite dev server (host: true, PWA devOptions enabled)
npm run lint         # ESLint (typescript-eslint + react-hooks + @tanstack/router rules)
npx tsc -b           # Type check. `npm run build` does NOT type check; only build:war / build:android do
npm run build        # vite build -> dist/
npm run build:war    # tsc + build + copy WEB-INF/META-INF into dist (Windows `xcopy`) for Tomcat deployment
npm run build:android
```

There is no test framework in this repo.

Env vars (`.env`, `.env.production`): `VITE_API_URL` (backend base URL), `VITE_BASENAME` (used as the Vite `base`, the router `basepath`, and the cookie `path`), `VITE_LOCATION_ID`.

Deployment target is Tomcat: `WEB-INF/rewrite.config` rewrites non-asset paths to `index.html`. `version.json` is copied into `dist/` and polled by `useVersion` every 30s. When the version changes, the page force-reloads, so bump `version.json` on release.

## Architecture

**Routing (TanStack Router, file-based).** `src/routeTree.gen.ts` is generated by the `tanstackRouter()` Vite plugin, so never edit it by hand. Folders and files prefixed with `-` (e.g. `-components/`, `-users-modules/`) are colocated non-route modules. Two separate authenticated areas:
- `src/routes/_non-vendor/` — pathless layout for non-vendor users. `beforeLoad` redirects to `/login` when `useNonVendorAuthStore` is not authenticated. `invoices/route.tsx` also gates the whole section on the user's fetched status being `APPROVED` (otherwise it renders `AccessRestricted`).
- `src/routes/admin/` — admin area. Redirects to `/admin-login`.
- Breadcrumbs come from `staticData.breadcrumb` on routes (an i18n key or a function; typed in `src/@types/router.d.ts`) and are resolved by `components/breadcrumb`.
- List pages keep their filters and pagination in URL search params, validated with zod schemas from `src/validation/*` via `validateSearch`.

**Auth.** Two independent zustand stores (`src/stores/`) backed by cookies scoped to `VITE_BASENAME`: `non-vendor-profile` for non-vendors, and `admin-profile` + `admin-token` for admins. `src/api/axiosInstance.ts` attaches only the admin bearer token and handles 401 by refreshing via `/rest/auth/refresh`. Login and register calls in `auth.api.ts` use plain `axios`, not the instance. `src/autoLogout.ts` signs out after 30 minutes of inactivity.

**Data layer: three layers per domain** (`non-vendor`, `admin`, `vendor`, `item-master`, `auth`):
1. `src/api/<domain>.api.ts` — thin async functions that return `response.data` typed as `TResponse<T>` (`{ message, data?, pagination?, errors? }`).
2. `src/queries/<domain>.queries.ts` — a hierarchical query-key factory (`nonVendorKeys`, …), a `<domain>Queries` object of `queryOptions(...)`, and `use…Mutation` hooks that invalidate the relevant keys. Components consume these with `useQuery(nonVendorQueries.x(...))`.
3. `src/types/*.type.ts` for DTOs and `src/validation/*` for zod (v4) schemas used by forms and search params.

**Domain terms.** The "invoice" UI maps to backend **portal requests** (`/rest/portal/non-vendor/portal-requests`, types in `portal-request.type.ts`). The older `non-vendor-request` endpoints are still used for settlements and files. "PPh 23" is labelled "Bukti Potong" in the UI. Statuses live in `src/enums/document-status.enum.ts` (`DOCUMENT_STATUS` + colors).

**UI.** shadcn/ui (new-york) components in `src/components/ui`, Tailwind v4 via `@tailwindcss/vite` (no tailwind config file; theme is in `src/index.css`), `lucide-react` icons, `sonner` toasts, TanStack Table through the shared `components/data-table.tsx` + `data-table-pagination.tsx`, and column definitions in colocated `use-…-columns.tsx` hooks. The React Compiler (babel plugin) is enabled. Path alias: `@/` → `src/`.

**i18n.** `react-i18next` with a single `common` namespace in `src/locales/{id,en}/common.json`. Default and fallback language is `id`. Keys are type-checked against the **Indonesian** file (`src/@types/i18next.d.ts`), so add every new key to both files, starting with `id`. User-facing strings should use `t(...)`.

## Conventions

- TypeScript strict with `noUnusedLocals`/`noUnusedParameters`; do not use `any`.
- `plans/` holds Indonesian implementation-plan markdown files (one per feature, `plan-<feature>.md`). They are written as detailed step-by-step instructions meant for another AI model to implement. When asked to write a plan, follow that format and do not write code.
- Commit messages use Conventional Commits with a scope, e.g. `feat(invoice): …`.
